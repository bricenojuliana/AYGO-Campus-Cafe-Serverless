The smoke run is the console output copied from CloudShell. It ran against the first deployment, before AWS client creation moved to the Lambda init phase; that change does not alter request handling, and the later evidence run repeats the concurrency, replay and fault checks on the current code.

Notes:

* **Cold start.** Both handlers create their AWS clients in the Lambda init phase, so that cost shows as `Init Duration` (about 370 ms) instead of inside the first invocation. The first request after a configuration update took 836 ms client-side. Cold starts are reported separately from the p95 (43 ms over 20 sequential GETs).
* **Fault isolation.** With Catalog unreachable (DNS failure, 1313 ms) or not answering (blackhole, 4953 ms), Orders returns 503 `CATALOG_UNAVAILABLE`, stores neither an order nor an idempotency record, and answers within the 12 s Lambda timeout.

## Not verified

* **Least privilege at runtime.** In the Learner Lab the functions use the shared `LabRole`, because the lab forbids `iam:CreateRole` (see README §2.3). The least-privilege roles in `template.yaml` are checked by `tests/infra/test_template.py` but were never deployed.
* **Real concurrency in local tests.** moto does not isolate DynamoDB transactions across threads, so concurrent creation is verified only against AWS (both runs above).
* **Browser journey.** The UI was checked against the deployed API for the menu and the order lookup only. Submitting, reloading, retrying and cancelling from the browser are covered by the API checks above, not by an automated UI test.
